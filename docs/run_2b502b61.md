## Protection added for subsequent runs

- Local periodic checkpoints every 100 updates, independent of MLflow deployment
  model logging. They include weights, Adam state, RNG states, config, and the next
  iteration number.
- A `best.pt` checkpoint selected using a fixed-seed, four-episode validation
  batch, initially and every 25 updates. Validation does not render videos or
  consume the training RNG stream.
- After two consecutive validation scores fall more than both 50% and 25 return
  units below a best score of at least 50, restore the best model **and Adam state**
  and halve the learning rate. Current sample/iteration progress is retained.
- A failed/non-finite optimizer update restores its pre-update snapshot. Losses,
  gradients, parameters, and optimizer buffers are checked before accepting an
  update.
- Errors and interrupts save the last finite state plus `training_failure.txt`
  where Python can execute the error handler. Normal exit also saves `latest.pt`.
- Checkpoint replacement is atomic, so a failed write does not replace a valid
  checkpoint with a truncated file. Hard process kills can still lose work since
  the most recent checkpoint.
- New telemetry includes gradient norm, learning rate, validation scores and
  rollback events; progress and Python failure traces also reach the Hydra log.

These mechanisms preserve a recovery point and respond to detected degradation.
They do not guarantee that every update improves the policy or protect behavior
outside the validation scenarios. The actor–critic objective itself is unchanged.
